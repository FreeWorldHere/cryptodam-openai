# Security and responsible reporting

Do not report security issues containing private information in public GitHub issues, discussions or pull requests.

Contact **stuporeinvestment.kj@gmail.com** or use the contact details at [CryptoDam support](https://www.stuporeinvestment.com/contact). Start with a sanitized description: the affected public feature, approximate time, observed impact and steps that do not expose another person's data. Do not attach passwords, tokens, API keys, authorization codes, private keys, recovery phrases or personal account exports. If sensitive evidence is necessary, ask how to provide it securely before sending it.

These documents do not authorize penetration testing, access to another account, bulk data extraction, financial actions or changes to the shared service. Do not exploit an issue beyond what is needed to describe your own observation. Follow the service's [terms](https://www.stuporeinvestment.com/terms).

This public repository contains the connection package and its public documentation, not the hosted application or backend implementation. Its existence does not certify the backend or establish that runtime security checks have passed. Required authentication, MFA, scopes, tenant isolation and application permissions remain authoritative.

Support is handled by the operator; this repository does not set up automated mailbox monitoring or promise a separate security-response deadline. See the [privacy policy](https://www.stuporeinvestment.com/privacy) for data-handling and applicable request procedures.
